# 文章に関連する立体と、その面を流れる文字

2026-09-30 / 保存版 `prototype-v0.5.0` / Apple M5・32GB

**文章から関連する形を選ぶ・生成する処理と、その面を蓄積した文字で覆って動かす表示を、別の試作として実装した。** 同じ文章を複数の方式へ通し、見た目、処理時間、誤りを比較できる。元のアプリ、入力原稿、設定には変更を加えていない。

## 試す入口

- [比較画面](http://127.0.0.1:4183/)：Enterで文章を追加。「比較」で形の取得方法、文字の流れ、母体の揺らぎを変える。生成済みのじょうろ・傘・帆船などは待たずに読み込める。
- [連続入力の画面](http://127.0.0.1:4183/src/writing-preview/index.html)：生成中も文章を加えられる。操作を送信ごとに選び、原文はそのまま履歴へ残す。
- [GitHub](https://github.com/KOSEIHAMAYA2077/semantic-glyph-lab)：コード、人工例、失敗を含む記録。重みと個人データは含めない。

このMacで止まっている場合は、リポジトリのフォルダーで `python3 tools/run-lab.py`。取得済みの環境を起動するだけで、別の環境を変更しない。[再開と新規導入の違い](setup-scope.md)

まず比較画面で `花瓶`、続けて `四角くねじれた` を試せる。未知の形を作りたいときは「文章→画像→立体」を選び、例えば `取っ手が二つ付いた丸い花瓶` と入力する。約数十秒の処理になり、細部が期待どおりになるとは限らない。

連続入力画面では「文章から形を作る」で上の文を送り、待っている間に「今の形を変える」で `四角く`、「文字だけ加える」で別の文を送れる。文字は先に表面へ加わり、後から届いた形にも引き継ぐ。「受理」は原文を受け取った意味で、形が正しく生成できたことを示す評価ではない。再読込すると原文と状態は消える。

## 何を比較し、どう判断したか

| 方法 | 得られたこと | 採用範囲 |
|---|---|---|
| 24種類の意味検索 | 言い換えから手続き形状を選べる。初回の固定24問では21問で対象一致。 | 即座の変化に使う。カタログ外の形の生成とは区別する。 |
| 言語モデルによる部品合成 | 花瓶と木など、複数の既知部品を組める。 | 比較用。位置や部品数、接続を間違えるため、任意のモデル制作とは扱わない。 |
| 日本語→8Bの物体説明→Shap-E | 日本語から新しいメッシュを得て文字面へ通せた。 | 未知物体を試す直接生成の基準。取っ手など細部の欠落が残る。 |
| 日本語→8B→画像→TripoSR | じょうろでは注ぎ口・取っ手を読み取りやすい例が得られた。 | 未知形のもう一つの経路。薄い傘や裏面などは崩れ、常に直接生成より良いわけではない。 |
| 既存3D素材の検索 | 521件のメタデータを調べ、花瓶・じょうろ・剣の3素材を取得。 | 3候補を表示して利用者が選ぶ。未所蔵の馬にも高いスコアが出るため、自動採用しない。 |
| 文章の自動振り分け | 8B・14B・4B Instruct、二段階処理を比較した。形式が正しくても対象・操作を誤る。 | 不採用。連続入力版は新規作成・編集・維持を利用者が指定する。 |
| 文字表面の描画 | 三方向の投影で、UVを持たない生成形も文字で覆える。文字単位の面上移動も比較した。 | 既定は面を覆うテクスチャ。斜面での混ざりや文字の伸びは残る。 |
| 流体らしい渦 | 2Dの速度・圧力計算と逆写像を面へ投影した。補間を修正し、弱い流れの60秒比較では折返し0。 | 実験用。5分で文字が伸び、10分で折返しが生じる。3D曲面固有の流体ではない。 |

同じ日本語の帆船・開いた傘・じょうろを2方式で作った[6形状の比較](../experiments/end-to-end/RESULTS.md)では、形ごとに有利な方式が違った。各1seedの少数例であり、モデル全体の優劣を決める評価ではない。語義と見た目の判定はエージェントの読解・画面確認で、ユーザーテストや人間の参加者による研究ではない。

## 今後の実装はどう組むか

```text
文章 ──→ 原文・色・追加時刻 ──────────────────→ 文字の表面
  └──→ 対象と特徴 → 形の検索／合成／生成 → 三角メッシュ ──┘
```

原文の保持、文章の解釈、形の取得、表面の動きを独立させる構成が扱いやすい。文字は入力直後に反応させ、重い生成だけを待たせる。これで生成待ちの間に書き続けても文字が消えず、古い応答が新しい選択を上書きしない。

次に学習を試すなら、巨大な3D生成モデルを一から作る前に、**文章から「対象・特徴・数・関係・新規か編集か」を取り出す小さなモデル**を対象にする。今回の誤りと固定評価例を材料にし、別に用意した未知の文で確かめる。形との対応には[Text2Shape](https://arxiv.org/abs/1803.08495)、検索には[OpenShape](https://arxiv.org/abs/2305.10764)、手続きツールとの組合せには[3D-GPT](https://arxiv.org/abs/2310.12945)が参考になる。これらの学習を今回再現したわけではない。[研究調査](language-to-shape.md)と[詳しい構成・学習案](implementation-options.md)へ整理した。

自動振り分けは、モデルを大きくするだけでは十分でなかった。今後も誤りを無理に隠さず、対象不明・曖昧・生成失敗を区別する。一定周期の意味更新、他のアプリでの執筆との連動、日記保存、任意の部分だけを編集する機能は、この別版にはまだ接続していない。
