# 連続入力のCPUハーネス

2026-09-30。UI未接続の契約とスケジューラを独立に実装した。意味ルータのv1を不採用としたため、ここで成功したことを、文章の意味を正しく扱えるという結果に読み替えない。

## 確認した動作

- 受理したraw文字列は別の台帳に順序どおり保持。形の処理は非同期で、一度だけ文字追加hookを呼ぶ。
- 解釈と生成は単一workerで処理し、重い呼び出しを同時に二つ行わない。待機上限は8件で、超過は受理前に拒否する。
- 未知形を生成している間の追記は、生成後の採用より先に解釈する。同じ対象の属性編集は最新の属性で採用し、keepで生成が無効化され続けない。
- 新しい対象や手動resetが来たら、前の生成や遅いGLB読込の結果を採用しない。古いエラーも表示状態を上書きしない。
- 解釈や生成の失敗時にも受理済みの原文は残る。明示的な再試行で文字を二重追加せず、無制限の自動再試行はしない。
- APIへ渡す操作は有限な範囲のJSON。未知キー、空の編集、範囲外の数、NaN/Infinity、数値文字列、bool等を拒否する。

`src/intent.test.ts` と `src/continuous.test.ts` の67件が通過。遅い応答の順序を制御できるCPUモックを用い、生成中の属性変更・色だけの追記・既知形への変更・読込中reset・通信失敗・再試行・上限・同期例外を確認した。TypeScriptの型検査も通過。既存の単体試験と合わせて315件通過（v0.3の248件＋今回67件）。

実際の入力欄、IME確定、LetterField、GLBデコーダ、WebGL、objectURLへの接続は未実装・未検証。既存6方式のmain/APIは変更していない。上記の原文保持はプロセスのメモリ内だけで、ブラウザ再読込からの復元を保証するものではない。GPU実行や意味精度の評価にはこのモック試験を使わない。
