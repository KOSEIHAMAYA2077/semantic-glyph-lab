# 操作判定と対象説明を分ける実験 v2

語義・内容の確認は担当エージェントによる原出力の読解です。ユーザーや人間の参加者による評価は行っていません。JSON記録の `humanReview` 等のキー名は記録を保つためそのまま残しています。

2026-09-30。v1の24例を回帰として再利用し、別の人工12例を追加する。既存のAPI・画面・環境、v1の凍結ファイルは変更しない。モデルの追加学習や新しい重みの取得はない。

## 変更した構成

1. **操作判定**へ原文と現在の対象の英語説明・属性を渡す。カタログ一覧は渡さず、`new / edit / keep` の一つだけを返させる。
2. **newなら対象説明**へ原文だけを渡す。現在の形、既知の24形状、操作の正解は渡さない。説明promptは、既存の8B説明実験とバイト単位で同じものを利用する。
3. **editなら属性差分**へ原文と現在属性だけを渡す。対象名や新しい形は出力させない。keepは後段を呼ばない。

新しい物体の出力は短い英語であり、既知form IDの選択はまだ行わない。数や形容もこの説明に残るかを確認する。英語に個数が含まれていても、後段の3D生成がその数を実現できるという保証にはならない。今回は立体の生成やUIへの適用を行っていない。

## 先に固定したもの

新規12例は15:47 JST、v2の操作・編集promptを書く前に [fresh-plan.json](fresh-plan.json) と [そのSHA256](fresh-plan-lock.json) を保存した。現物の英語説明付き編集、否定、属性と色の混在、複合物、未知の同一対象、明示的な作り直し、未対応の部位編集・個数・上限を含む。評価作成者は文を知っており、外部の盲検ベンチマークではない。

15:51 JSTにprompt・schema・runnerと参照するv1ファイルも [protocol-lock.json](protocol-lock.json) で固定した。各例・各段階は1回だけ。誤った結果を得てから例別辞書、正解を含むprompt、形式の修復、再生成は追加しない。

## 比較条件

[公式Qwen3-8B-MLX-4bit](https://huggingface.co/Qwen/Qwen3-8B-MLX-4bit)、revision `383413e909f3bc5303ce195ebbdf0339c5a1a2a3`、既存の検証済み4bitモデルと専用MLX環境を読み取り再利用する。公式non-thinkingの推奨に合わせ、温度0.7、top_p0.8、top_k20、thinkingなし。各段階の直前でseed17に戻し、後段の有無で次の問題の乱数が変わらないようにする。一度のseedでの観察であり、複数seedの平均ではない。

出力上限は操作64 tokens、編集256 tokens、説明512 tokens。出力は厳格なJSONのみで、コード実行はない。モデルファイルのhashを再検査し、offline設定、remote code無効、PythonのIP接続拒否を使う。キャッシュだけ `.local/input-routing-v2-cache` に分ける。通常APIを呼ばず、記録する原文・出力は人工例のみ。

**v1との違いは二段階化だけではない。** prompt、出力契約、greedyから推奨samplingへの変更も含む。改善しても、その原因を一つに断定しない。v1の未知対象選択やcount差分と、v2の英語説明を同じ採点として集計しない。

## 評価の分け方

- 操作のschema成立と、期待するactionの一致。
- editへ進んだ場合の差分schema、求められたキー・値域の一致。
- newへ進んだ場合の説明schema、原文の名詞・数・部品・関係の保持。後者は原文との読解比較で原文と比較する。
- 段階別時間と合計時間。対象説明へ進まないkeepが多い集団と、全例で生成する集団の合計速度は同じ条件ではない。

24回帰例と12新規例を別集計する。v1の契約完全一致0/24は、意味の一致0/24を意味しない。例えば一つの球のcount省略は既定値なら正しく表示される。v1の記録とその採点は [そのまま保持](../input-routing/README.md) している。

同名の記録や、凍結したソースと異なるhashがあれば停止する。既存結果を上書き・削除しない。

## 結果

15:51〜15:53 JSTに36例を各1回実行して完了。**自動振り分けとしてはv2も採用しない。** 形式は改善したが、別の物体への変更を現在の物体の編集とする誤りが多く、入力の意図を安全に反映できない。API・UIへは接続していない。

| 指標 | 24回帰例 | 新規12例 |
| --- | ---: | ---: |
| 操作JSONのschema成立 | 24/24 | 12/12 |
| 期待したactionとの一致 | 9/24 | 7/12 |
| 後段まで含むschema成立 | 18/24 | 10/12 |
| newを期待する例 → 実際に説明へ進んだ例 | 11 → 0 | 4 → 2 |
| 本来editの例 → 差分まで契約に合った例 | 5 → 5 | 2 → 2 |
| 実際にeditへ進んだ数 / その差分schema成立 | 19 / 13 | 7 / 5 |

操作のJSONだけなら全例が形式に従った。一方、v1の回帰例でactionだけを見ると10/24から9/24になり、二段階と推奨samplingの組み合わせでも操作の区別は改善していない。v1の厳格な契約0/24と、今回のschema18/24を意味の精度が上がった数値として比較しない。

### できたことと、残った誤り

本来editである7例は、未知のじょうろの四角化、花瓶の縦長化、粗さの解除、個数変更、鐘の軽い曲げ、色指定と粗さ解除の併記を、それぞれ指定した差分にできた。これは「編集であることが正しい場合」の小さい条件付き結果であり、他の文章を編集と誤認する問題を打ち消すものではない。

| 確認した失敗 | v2の結果 |
| --- | --- |
| 新しい球、傘、じょうろなど | newへ進まず、editに分類。空の差分、または現在の形を長くする差分になった。 |
| 球への置き換え | editで四角さを0にするだけで、元の立方体を新しい球へ置き換えない。 |
| 鎖の連結、8個の円環 | 現在の形のcountを変えるだけで、対象や連結関係を失う。 |
| 四角くすることの禁止 | 四角さ0へのeditになり、禁止と解除の混同が残った。 |
| 色だけ、対象不明の指示語 | editへ進んで空の差分となり、後段schemaで拒否。 |
| 急須 | 現在のマグをkeepし、新しい対象を得られない。 |
| 胴だけの四角化 | 全体への四角さ1として出力し、部位指定を無視。 |
| 同じ物体を12個 | 未対応として維持せずcount12を出し、数値の上限検査で拒否。 |
| 上限2.5からさらに縦長に | editで2.5を再出力。値域には収まるが、変更できない要求を理解したとはいえない。 |
| 球の明示的な作り直し | count1のeditへ落ち、以前のねじれを消して新規にする意図を失った。 |

後段schemaの拒否は空編集7件とcount上限違反1件。拒否したため、この実験から不正な操作を実アプリへ適用することはない。許可された数値だけの出力でも、対象の取り違えや禁止の誤読は形式検査で判定できない。

### 新しい対象の英語説明

説明段階へ進んだのは新規12例中の2件だけだった。

| 人工例の内容 | 返った説明 | 観察 |
| --- | --- | --- |
| 歯車を直立させる | `a gear standing upright` | 歯車と直立を保持。 |
| 橋の下に小さい舟が浮く | `a small boat floating under a bridge` | 舟・橋・上下関係・小ささ・浮くことを保持。 |

この2件は原文との読解比較で内容保持を確認できた。ただしnewを期待した全15件のうち13件は操作段階で止まったため、それらの説明品質は今回測れていない。「説明が2/2でよかった」を未知対象全般の正確さに広げない。新しい形の生成も実行していない。

### 採否と次の仮説

現行の手動による方式選択を維持する。属性編集を明示してから数値差分を作る用途には検討の余地があるが、原文から自動で操作を選ぶ入口にはまだ使わない。既知形へ無理に当てはめないためカタログを外しても、現在の形を編集する方向への偏りは残った。

次に切り分けるなら、`new / edit / keep` を `replace_subject / change_parameters / append_text` のように具体的なラベルへ変える比較が候補になる。一般的な「編集」に対象の置き換えも含めてしまう可能性はあるが、今回の結果だけからその原因とは断定できない。この案の推論は行っていない。モデルの違いを比較する場合も、この凍結条件を維持して別の記録へ保存する。
