# 文章から形の変更意図を分ける独立実験

2026-09-30。現在の形を文脈として与え、入力を「新しい物体」「今の物体の属性編集」「形を維持」に分ける。文字の追加・色指定は別の処理であり、この出力から生成しない。既存の画面、API、Python環境には変更を加えていない。

## 先に決めた規約

`action` は `new / edit / keep`。`new` だけが `target` を持つ。既知の24形状と対象が一致するときは `form`、それ以外は短い英語の `object_en` を返す。この二つは同時に指定しない。`edit / keep` は `target:null` とし、生成した未知物体を、似たカタログ形へ置き換えない。

`changes` は指示された属性だけの差分。四角さ0〜1、縦長さ0.5〜2.5、ねじれ/曲がり−1〜1、粗さ0〜1、同一物体の数1〜8を扱う。値は現在値へ加算する量ではなく、変更後の値。`keep` は空、`edit` は一つ以上の属性を要求する。色・全体サイズ・速度を、この属性へ無理に代入しない。

同じ物体を名指すだけなら維持し、同じ物体への修飾なら編集する。明示的な作り直しは新規にする。属性の変更を禁止することと、既存の属性を解除することを区別する。複数種類の物体、または支持できない連結・配置を含むものは、対象の関係を保った未知の複合物とする。単に `count` を増やす処理で、鎖の連結を表現したとは扱わない。

現在の形には `target` と全属性を渡す。生成GLBの文脈は既知の代理IDではなく、元の物体を表す英語説明とする。状態遷移は `new` が既定属性から作成、`edit` が現在属性へ差分適用、`keep` がそのまま。LLMが出したPythonやJavaScriptを実行する箇所はない。

## 固定した評価

[人工24例](evaluation-plan.json) と期待するaction・主要属性を推論前に作成した。未知のじょうろの四角化、抽象文、否定、色だけ、既知形の属性、同一物体の維持、未知名詞、複数の物体、連結した同種部品を含む。主目的は、とくに未知名詞を近い既知形へ寄せる失敗の観察。

読み取りレビューで規約を確認した後、15:41 JSTに [prompt](prompt-v1.txt)、評価文、schema、runnerのSHA256を [protocol-lock.json](protocol-lock.json) へ保存した。同じprompt・greedy・thinkingなし・最大384 tokensで、各例一度だけ生成する。形式不正の再試行、例別の辞書置換、結果を見た後の期待値変更はしない。

自動採点はaction、対象の既知/未知、属性キー、事前に決めた値域を調べる。形容の強さの範囲は実装上の規約であり、日本語の唯一の正解ではない。未知対象の英語が元の物体・部品・関係を保つかは、JSONの形式とは別に人が確認する。これは本実験で初めて入力する24例であり、モデルの事前学習に一切似た文がないと確認した評価ではない。

## モデルと実行の範囲

[公式Qwen3-8B-MLX-4bit](https://huggingface.co/Qwen/Qwen3-8B-MLX-4bit)、revision `383413e909f3bc5303ce195ebbdf0339c5a1a2a3`、Apache-2.0。重みは既存の検証済み4,351,884,216 bytesを読み取り再利用し、追加ダウンロードも量子化もしていない。[既存の取得記録](../translation-model/qwen8-manifest.json) と固定した公式SHA256を再照合してから読み込む。

独立プロセスから既存の専用MLX環境を使う。キャッシュは `.local/input-routing-cache` に分け、Pythonバイトコードを書かない。offline設定とIP接続拒否を併用し、`trust_remote_code=False`。通常の4188サービスや既存のサーバーコードは呼ばず、変更もしない。記録する入力とraw出力は、この人工24例だけ。

公式の非thinking時の推奨温度0.7とは異なり、今回は条件を固定して比較するためgreedyを使用する。単独の温度・prompt条件から、モデル一般の性能を主張しない。

## 再現と境界試験

```sh
python3 -B experiments/input-routing/test_schema.py -v
.local/translation-model-qwen8-venv/bin/python -B experiments/input-routing/evaluate.py --run another-run-name
```

実推論は他の重いGPU処理と時間を分ける。同名の結果があれば停止し、既存の記録を上書きしない。凍結済みファイルのhashが違う場合も評価を開始しない。

CPU境界試験12件は推論前に通過。空/二重target、未知のform ID、許可しないキー、bool・NaN・無限大・巨大整数、数値文字列、整数でないcount、上限・下限、不正Unicode、重複JSONキー、形式外の追加文章、空編集、未知形の保持と状態遷移を確認した。形式検証を通っても意味が正しいとは限らない。

## 結果

15:41〜15:42 JSTに24例を各1回実行して完了。**v1は採用しない。** APIやUIへの接続はしていない。元のprompt・評価・schema・runner・raw出力を変更せず、同じ問題でのやり直しも行っていない。

| 指標 | 今回の結果 |
| --- | ---: |
| JSONとして構文を読めた出力 | 24/24 |
| 厳格な出力schemaに合った出力 | 3/24 |
| 事前に定めた操作契約と全項目一致 | 0/24 |
| raw出力のactionだけが期待と一致 | 10/24 |
| 未知対象7例で、独立した英語targetを返した出力 | 0/7 |
| 1例の推論中央値 / 最小 / 最大 | 2.391秒 / 1.882秒 / 3.194秒 |

0/24は**厳格な操作契約の一致**であり、すべての出力の意味が完全に誤っていたという数値ではない。たとえば球を一つ作る文は、`new / sphere` が正しく、明示された `count:1` を省いたため契約では失点した。実装の既定値を使う最終表示は要求どおりになる。この観察は残すが、評価後に期待値を緩めて事前の点数を変えない。

形式不正21件の最初の拒否理由は、20件が `edit / keep` にもtargetを出したこと、1件が `changes` に属性でないformを入れたこと。未知のじょうろを四角くする、花瓶を少し長くする、粗さを0へ戻すなど、rawの操作・属性は妥当でも、targetの再出力で受理できなかった例がある。一方で、余分なtargetを除去するだけでは次の意味の誤りは直らない。

| 人工例で調べた点 | rawで起きたこと |
| --- | --- |
| 四角くすることの禁止 | `edit` で四角さを0にし、禁止を解除操作と取り違えた。 |
| 漏斗 | 現在の円錐を縦長さ2.5へ変える操作になった。 |
| じょうろ | 現在の花瓶を縦長くし、要求していない粗さも追加した。 |
| 急須 | 現在のマグを維持し、未知の対象を表せなかった。 |
| 鎖状につながる輪 | `ring / count:3` とし、連結関係を失った。 |
| 全体を大きくする未対応操作 | 縦長さへ代入した。 |
| 対象が分からない指示語 | 現在の形へ縦長さ・曲がりを勝手に追加した。 |
| 椅子の上の鳥、開いた傘 | `keep` として、新しい対象を取り出さなかった。 |

モデル読込呼び出しは1.885秒、MLX allocator peak約5.11GB、プロセス最大RSS約3.80GB。読み込み前に4.35GBの重みを検査済みの条件で、完全な冷起動ではない。二つのメモリ指標は加算しない。PythonのIP接続拒否で記録された接続試行は0。

生の結果は [run-01.jsonl](run-01.jsonl)、設定と時刻は [run-01-runtime.json](run-01-runtime.json)、集計は [summary-v1.json](summary-v1.json)。20件の形式違反が目立つが、形式を直せば意味も直るとは判断しない。逆に、これだけで8Bモデル全般に意図解釈が不可能とも判断しない。今回の長いprompt・greedy・一度の条件に限った結果であり、公式推奨samplingは未比較。

次案は操作判定と対象説明を二段階に分けること。最初はカタログを渡さずactionだけを決め、新規対象なら現在の形を渡さず説明を生成する。編集の場合だけ現在属性から差分を出す。currentやカタログへ引き寄せられる失敗を分けて観察する仮説で、v1の結果から改善を保証するものではない。[独立したv2実験](../input-routing-v2/README.md) へ進め、v1は保持する。
