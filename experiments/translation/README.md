# 日本語から短い立体説明へ

日本語の文章を、Shap-Eへ渡す短い英語の物体説明へ変換する。既存のローカルQwen3-4B-Instruct-2507 / 4bitを再利用し、単語辞書の置換に閉じず、形容・個数・部位・物同士の関係が残るかを調べる。新たな重み取得や学習は行わない。

## 接続

```sh
.local/composition-venv/bin/python server/composition.py
```

`127.0.0.1:4185` の `POST /describe` に `{"text":"人工例文"}` を送る。成功時は `{"text_en":"short English object description","elapsedMs":...,"model":...,"attempts":...}`。英語を `4186/generate` へ渡すかどうかは呼び出し側が決める。このAPI自体は立体生成を起動しない。

既存の `/compose` と同じモデル・ロックを使い、同時推論は1件。既存の部品合成用プロンプトと温度は維持し、文章変換だけ専用プロンプトとgreedy decodingを使う。入力2000文字・本文16KiB・Host/Originの制限も共有する。モデルの出力は `{"text_en":"..."}` の1フィールドだけを許すJSONとして検証する。コードの実行やJSONの自動修復はない。

返す説明は300文字以内の印字可能ASCIIに制限。45語以内もプロンプトで指示するが、実際のCLIP 77 tokenの最終判定は4186の生成APIに残す。モデルが形の対象を特定できないときは空の説明を許し、422で明示する。空回答を再試行して架空の物体を捏造させない。JSON形式が崩れた場合だけ1回の再生成を許す。出力は1回512 tokensまで。

アクセスログと入力・出力のファイル保存は行わない。既存の専用venvとオフラインMLX推論を再利用し、文章を外部へ送信しない。モデルの配布元、revision、ライセンス、取得容量、safetensorsと依存の確認は[元の部品合成記録](../composition/README.md)を参照。

## 比較方法

初回推論より前に [evaluation-plan.json](evaluation-plan.json) へ人工例13件を固定した。肯定と否定、左右、個数、入れ子の関係、日常の文章、空想上の物体、対象を特定できない文、本文に紛れた別の指示を含む。これらは人が用意した小規模な実験例であり、一般的な翻訳能力を測るベンチマークではない。

各例の元文、期待内容、HTTP応答、時間、計画ファイルのSHA256を版付きJSONLへ保存する。これは明示的な人工例の研究クライアントだけの動作であり、通常のAPIには保存処理がない。成功した説明は実際のCLIP tokenizerでも確認する。翻訳が正しくても、Shap-Eがその形を生成できるとは限らないため、意味の保存と立体の品質を混同しない。

```sh
.local/composition-venv/bin/python experiments/translation/evaluate.py --run run-01
```

同名の結果ファイルは上書きしない。再実験は新しいrun名を使い、同じ例を再利用した比較として記録する。

## 実測と採否

| 条件 | HTTP結果 | 時間の中央値 | 実CLIP tokenizer |
| --- | --- | --- | --- |
| Run 01: 英語指示のみ | 13件すべて200。ただし対象不明2件でも説明を捏造 | 0.685秒 | 13/13が77 token以内 |
| Run 02: 日本語の補足と汎用4例を追加 | 具体的対象11件は200、対象不明2件は意図どおり422 | 0.812秒 | 成功11/11が77 token以内 |

Run 02は同じ13例を再利用した改善比較であり、初回・未見評価として扱わない。対象別の正解訳をコードへ追加していない。日本語の補足と例は[変更前](prompt-01.txt)・[変更後](prompt-02.txt)に残す。補足例は評価文と別の文だが、初回の失敗を見て設計したため、独立した評価ではない。

現行候補はRun 02。所要時間は0.596〜0.973秒で、再生成はなかった。起動・モデルロードを除くHTTP時間であり、最初の例は起動後の初回要求。成功した説明は6〜80文字、実CLIP 4〜17 tokens。モデルの出力は短くても、次の意味の誤りが残った。

| 人工例の狙い | Run 02の観察 |
| --- | --- |
| 高い陶器の花瓶、左右の取っ手 | 材質・高さ・左右を保持。 |
| 球ではなく立方体 | `a cube` となり否定対象を除去。Run 01で付け足した台も消えた。 |
| 細長い剣の周りに3つの輪 | 3つ・周囲・浮遊・長さを保持。細さは明示しない。 |
| 店で見た、表面のざらざらした巻き貝 | 複数の貝と店の景色を残し、粗さを落とした。修正が必要。 |
| 背もたれがハートの椅子 | 物体と部位の関係を保持。 |
| 花瓶から木、その枝に鳥 | 花瓶と鳥の関係は残るが、木を `stem of wood` と訳した。木全体の形にならない恐れ。 |
| 花瓶ではなく急須 | `tea set` と訳し、単体の急須から茶器一式へ意味がずれた。取っ手と注ぎ口は残る。 |
| 浮く島の上に小さな家 | 対象と配置を保持。 |
| 四角い雲と三角形の雨粒 | 両方の形と上下関係を保持。 |
| 皿の上のみかん2個、左だけ細長い | 個数・皿・左側の細長さを保持。みかんは一般的な `oranges` に広がった。 |
| 感情だけ／指示語だけの文 | 2件とも対象不明で422。Run 01の抽象的な埋め合わせは抑えられた。 |
| りんごの説明にコードを書く指示が混入 | `a red apple` のみを返した。この1例は一般的な攻撃耐性の証明ではない。 |

**英文候補を見える場所へ出し、生成した形が元の文と違う場合に、訳と形のどちらでずれたか分かる使い方が適する。** 名詞と関係を正しく訳す保証はなく、対象不明の拒否もこの2件で改善した観察に留まる。プロンプトの追加を続けて同じ13例だけを正解に寄せることはせず、ここで失敗を残す。

生の人工例応答は[Run 01](run-01.jsonl)・[Run 02](run-02.jsonl)、token検査は[Run 01](run-01-clip.json)・[Run 02](run-02-clip.json)。`summary.json` に時間集計・設定・入力計画とプロンプトのSHA256を保存した。訳文だけの比較であり、この13文すべての立体生成は行っていない。
