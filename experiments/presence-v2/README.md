# 文字の面 v0.6 — 入力できる比較版

固定した44字を見せる研究画面だけでは、初期の「文字が身体になる」体験を失っていた。近い@、Enterで開く入力欄、入力位置からの吸収、色の保持を持つ別入口へ戻し、一字ずつ面上を運ぶ方式を比較する。元の4173、4183、4192の版・ソース・サーバーは変更しない。

最初の手続き版の機能を引き継いで形を増やしたものは、[ai-game-lab の別ブランチ](https://github.com/KOSEIHAMAYA2077/ai-game-lab/tree/feat/glyph-word-shapes-v2)。本書は、任意のメッシュへ文字を載せる側の描画実験を記録する。

## 試す

```sh
npm ci --ignore-scripts
node experiments/presence-v2/serve.mjs
```

[試遊入口](http://127.0.0.1:4193/src/presence/index.html)。この入口も `npm run build` に含む。OS専用の推論環境は使わず、既存のThree.jsとブラウザだけで動く。

- Enter → 文章 → Enter。入力した文字が渦を巻いて中心へ入る。
- `白い球体`、`青い花瓶`、`四角くねじれた`、`赤い剣`など。認識は既存の24種類の明示語と属性。未知の語からモデル生成する入口ではない。
- 「◇ 形」で形、文字の大きさ、流れ、母体の揺らぎを選べる。形を替えても文章は保持する。
- 「表示」で、新方式・以前の面歩き・投影を比較する。研究用の情報を常時重ねない。
- 「じょうろ（生成済み）」は以前に保存したメッシュ。同じ表示と属性編集を適用できる。**Powered by Stability AI**。出所は[既存manifest](../../public/end-to-end-models/manifest.json)。新しい推論・ダウンロードは行っていない。

入力はページのメモリのみ。再読み込みで消える。外部送信やOS入力の取得はしない。文字数に比例した成長・日記・執筆連動は手続き版側に残る機能で、この描画比較入口では実装していない。4096枚の文字平面で入力を繰り返し、面を覆う。

## 変えた点

- 累積した文字画像を引き伸ばすのではなく、文字の中心を三角形の隣接関係に沿って移動させる。位置のリセットや再出生はしない。
- 文字平面の軸を直交し直し、字形に母体のせん断・伸長を掛けない。母体の揺らぎと面上の文字の移動は独立。
- 初期の面積に応じた配置と、近隣距離を使った候補選択で、最初から文字が極端に重なる場所を抑える。字の大きさも面積に合わせる。
- 前後と面向きに応じた明暗、黒い深度用の面、近い構図を組み合わせる。立方体では斜めから見える初期視点と、全体が収まる画角を確認した。
- 追記時に既存文字の唯一の表示片を残し、余分な複製だけを新しい文字へ割り当てる。交換は旧字の消失→新字の出現とし、二重像を混ぜない。
- 同じ形・同じ属性を追記しただけなら、面上の流れを作り直さない。流速0でも新しい文字の色・入替は反映し、全体停止時は止まる。

速度場は既存の[面上の流れ](../advection/RESULTS.md)に基づく、三角形上のスカラー場から作った接線方向の運動。新しい流体論文の再現、任意の形上の完全な物理流体、字の重なりを無くすシミュレーションではない。

## 比較と修正

1. 固定文字比較と初期版を見比べ、自由入力・吸収・成長の欠落、小さく暗い格子状の文字を確認した。
2. 新方式で球・立方体・花瓶・生成じょうろを通常操作で表示。球と花瓶では明瞭な個々の字が残った。
3. 立方体を球と同じ距離へ近づけると、長時間の回転で下端が切れた。形の外接球と操作部の余白を使って画角を決める方式へ修正した。
4. 回転が進んで立方体の正面だけになりやすかったため、回転を遅くし、初期の斜め視点を深くした。
5. 独立レビューで同形名の追記による再初期化、流速0時の新字フェード停止、絵文字の入力上限メッセージの矛盾を発見して修正した。

## 実施した検証

- 単体466件、型検査、通常・連続入力・今回の3入口のbuildが通過。
- [check-v4](check-v4/results.json): Enterの導入、通常入力、形・方式の切替、元文字と色の保持、同形追記での流れの保持、生成メッシュへの属性追記、IME合成イベント、空入力、停止/再開、小さい画面。16項目が通過。JS/consoleエラー・外部リクエスト0。実OSの日本語変換は未確認。
- [endurance-v1](endurance-v1/results.json): 球・花瓶・立方体をそれぞれ300秒相当、固定刻みで進めた。4096文字の中心を途中で再配置せず、境界停止・反復上限停止・GLエラー0。各300秒相当の実計算は約12〜16秒であり、5分間の実時間放置ではない。
- [final-v1](final-v1/results.json): 最終の入力・画角修正後にも球・花瓶・立方体の300秒相当を再確認し、境界停止・反復上限停止・GLエラー0。流速0の同形追記、2001個の絵文字、4001字の入力を消さずに分割案内する動作など6項目が通過。計測前後で3つの主要ソースのSHA256が一致した。
- 同じfinal-v1では別ページで球の4096枚を実時間で観測した。240フレームの準備後、600区間（約10秒）のrequestAnimationFrame間隔は中央値16.7ms、p95 16.8ms。Chrome 154 headless / Apple M5 / 1200×900 / DPR 1での結果。GPU処理時間、長時間の放置、一般的なWindows PCの性能を測った結果ではない。
- 新しい層のCPUテストでは、5分相当の移動後も字の基底の大きさと直交性、三角面内の中心、隣接面を跨ぐ連続性を確認。追記時の原字保持、借用した資源を破棄しないことも検査。

## 保持した途中経過

- [check-v1](check-v1/results.json)は初回の検査文に球と花の両方が入っており、球だけを期待した検査が失敗した。入力例の曖昧さを除いたv2以後で再確認した。成功扱いにはしない。
- check-v2/v3は、その時点の実装を確認した途中版。最終の操作画像はv4。初期の画角の失敗もそのまま保持した。
- endurance-v1は画角・入力上限・同形追記の最終修正前の記録。中心を運ぶ層自体は同じだが、最終入口の長時間検証と同一とは主張しない。
- final-v1は最終実装の記録。時刻前進による確認と、約10秒の実時間観測を分けて保存した。

## 残る制限

凹んだくびれや角では平面文字の隅が面へ隠れる。三角面を跨ぐと文字の向きが急に変わる場合がある。移動後の文字の重なりや薄い場所は残る。別の形への変更では配置を作り直し、メッシュを横断した文字の軌跡は保持しない。一般的なWindows PC・省電力・長時間の実負荷は未確認。研究用の入力例や自動検査で安定したことを、作品としての完成判定にはしない。
