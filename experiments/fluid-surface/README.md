# 2D流体場で文字の表面模様を動かす

2026-09-30。独立した表現実験。既存アプリの描画・入力・APIは変更していない。

**採否: 手動4点補間・弱い渦の版を、独立した比較用試作として採用する。mainの既定描画にはまだ入れない。** 球、花瓶、生成じょうろの面を白い文字が覆い、近隣の文字がゆっくり一緒に曲がる。線状の粒子や花火は使わない。ただし追加の600秒検査で文字の伸長と写像の折返しを確認した。常駐して字形を保ち続ける用途は未完成。任意の文字追加、母体の変形との組合せは今回の確認範囲外。

リポジトリのルートで次を実行する。既存サーバとは別の4190を使い、比較中に別のソース編集で画面が再読込されないようHMRを無効にしている。

## 実装と範囲

128×128の周期境界を持つ平面に速度を保持し、速度自身の移流、弱い外力、発散、圧力のJacobi反復、圧力勾配の減算を行う。発散と勾配は同じMAC格子に対応させ、`D(G(p))` が圧力方程式の差分と一致する。固定刻みは1/60秒、圧力は毎ステップ40反復。4個の渦の位置・強度・位相はseed 20260930で固定し、その中心だけをゆっくり動かす。線形抗力を入れる一方、物性値に基づく粘性・自由表面・障害物との衝突は解いていない。移流と圧力投影という基本構成の一次資料は [NVIDIA GPU Gems, Chapter 38](https://developer.nvidia.com/gpugems/gpugems/part-vi-beyond-triangles/chapter-38-fast-fluid-dynamics-simulation-gpu)。この実験のコードは新規に書いた。

流すのは文字画像のRGBではなく、元の位置への変位 `d`。出発点を逆にたどり `d_new(x) = d_old(x - Δt v) - Δt v` とし、毎フレーム元の文字atlasを引く。RGB画像を繰り返し低解像度の格子へ戻さないため、RGBの反復補間による累積ぼけは発生させない。ただし座標の伸び、斜め方向への投影、縮小時のフィルタで文字は読みにくくなり得る。

この2D変位を、同じ三角メッシュの3方向からの文字投影へ使う。**3Dの曲面に沿った流体シミュレーションではない。** 取っ手の周囲を物理的に回り込む流れ、面をまたぐ一意の文字経路、3D表面積の厳密な保存を保証しない。三平面投影の斜め面で文字が二重になる既存の制限も残る。母体は静止しており、黒い画素も深度を書く。

## 比較と修正

同じ44書記素の人工文字列を繰り返し、atlas 8×8、密度15、白文字、1280×900・DPR1、同じカメラと2.6単位への正規化で比較した。物体の自動回転は使わない。既存法は `createSurfaceMaterial` を読み取り再利用し、sinによる座標変形をそのまま比較した。既存法は時刻0でも座標が歪むので、両方式の時刻0の画像は一致しない。

| 版 | 変位の移流 / 補間 / 力 | 60秒の写像Jacobian最小–最大 | 非正のセル / 16,384 | 判断 |
|---|---|---:|---:|---|
| v1 | 一次 / GPU既定線形 / 1 | −1.261–4.150 | 46 | 渦中心に折返し。残すが不採用 |
| v2 | 誤差補正 / GPU既定線形 / 1 | −1.925–5.549 | 187 | 悪化。不採用 |
| v3 | 一次 / GPU既定線形 / 0.4 | −0.816–3.335 | 20 | 力を弱めるだけでは直らない |
| v4 最終 | 一次 / 明示4点 / 0.4 | 0.967–1.022 | 0 | 静かな比較用として採用 |
| 補足 | 一次 / 明示4点 / 1 | 0.740–1.183 | 0 | 流れが強く文字も伸びる。既定にしない |

弱い速度の1ステップは1セルより非常に小さい。GPU既定の線形補間を、シェーダ内で座標の小数部から重みを計算する4点補間へ置換すると、同じ力0.4・同じseedで折返しが消えた。精度不足の累積という推定を支持する比較だが、GPUの内部補間ビット数は測っていない。単に「高次の方法なら良くなる」とはせず、失敗した誤差補正版も残した。

Jacobianは逆写像の中央差分から測った指標。0以下のセルがないことは、全位置・無期限での厳密な非反転の証明ではない。平均約1も局所的な体積保存の証明ではない。

各旧条件はpreviewのquery、またはcapture引数で比較できる。

```sh
node experiments/fluid-surface/capture.mjs new-v1-record --hardware --force=1
node experiments/fluid-surface/capture.mjs new-v2-record --hardware --force=1 --corrected
node experiments/fluid-surface/capture.mjs new-v3-record --hardware --force=.4
```

previewのqueryは `?interpolation=hardware&force=1&transport=corrected` 等。失敗した補正は既定off。

## 数値検証

- CPU: 一様速度を投影しても変化しないこと、圧縮性の人工速度を投影すると発散が減ることの2テスト通過。型検査も通過。
- GPU: 周波数8/11の人工圧縮速度・100反復で発散RMSが1.60602→0.0218840、98.637%減。CPUの同一差分参照との速度最大差は2.98×10⁻⁸。実運転40反復とは別の検査。
- 最終版20秒: 発散RMS 1.3634×10⁻⁶→1.0273×10⁻⁸、99.25%減。
- 最終版60秒: 発散RMS 1.9245×10⁻⁶→1.9882×10⁻⁸、98.97%減。最大速度0.001425 UV/秒、最大変位0.06342 UV。全速度・変位・圧力・投影前発散の値が有限。
- リセットして同じ60ステップを2回進めた速度・変位の128サンプルは完全一致。停止中は60ステップのまま、再開12フレーム後は72ステップ。
- 最終比較のJavaScript例外、console error、WebGL error、外部要求はすべて0。

## 追加: 600秒まで積分すると字形は保てない

16:27–16:28 JSTに、同じseed・128²・力0.4・明示4点補間で、球の固定stepだけを延長した。[数値記録](long-run-v1/results.json) と3画像を別フォルダに保存している。別のUI検証と並行していたため、これはfps検査ではない。600秒は36,000ステップのシミュレーション時刻であり、600秒間の実時間放置ではない。

| シミュレーション時刻 | Jacobian最小–最大 | 非正セル | 最大変位 UV | 画像 |
|---|---:|---:|---:|---|
| 120秒 | 0.861–1.099 | 0 | 0.12459 | [画像](long-run-v1/sphere-fluid-t120.png) |
| 300秒 | 0.083–2.168 | 0 | 0.25084 | [画像](long-run-v1/sphere-fluid-t300.png) |
| 600秒 | −1.266–7.873 | 358 / 16,384 | 0.32221 | [画像](long-run-v1/sphere-fluid-t600.png) |

いずれも全値有限・GL error0、JS例外・console error・外部要求0。発散RMSの投影後/前比は順に0.0183、0.0235、0.0717で、速度場の発散低減は続いている。しかし300秒には多くの文字が細長く伸び、600秒には渦の大部分が線のようになった。**有限値や発散検査の合格だけでは、文字を読む表現としての成功を意味しない。** 蓄積した逆写像の大きな変形と数値誤差が残り、60秒の結果を無期限へ延長できない。

現段階でUIへ入れるなら、実験モードとして字形が長時間で伸びることを示し、文字本文や形状を失わず流れだけリセットできる導線が必要。周期的な自動リセットや2枚の写像のクロスフェードは今回実装しておらず、無段差で長時間維持できるとは主張しない。

```sh
node experiments/fluid-surface/long-run.mjs another-long-run-name
```
