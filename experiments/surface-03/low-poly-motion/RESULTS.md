# 低ポリゴンの揺らぎと面上の文字 — 画面確認

2026-09-30。修正後のmain画面をheadless Chromeで実操作した。ソースは変更せず、このディレクトリに検証スクリプトと結果を追加した。

## 確認した条件

- mainの4183を新規ページで開き、明示語モード、人工の白文字4,095字を2回に分けて入力。最初の`@`を含め4,096字。
- Kenneyの木・花・きのこを画面の選択肢から順に読み込み、「面を歩く」「回転off」「流れ0」「形の揺らぎ1」。テスト用の既存時刻操作で各モデルを0/8/16秒に揃えた。
- 9画面を保存し、すべて目視した。JavaScript例外、consoleエラー、WebGLエラーは0。外部ホストへのリクエストは0。
- 実レンダラーは`ANGLE Metal Renderer: Apple M5`。画面は1,280×900、pixel ratio 1、Chrome 154。ソフトウェアレンダラーではない。

## 判断

木の樹冠、花の茎・葉、きのこの傘・軸にある文字群が、形の曲がりに沿って位置を変えている。0/8/16秒で、面の中心付近の文字群がまとめて消える現象は見られなかった。先に追加した三角面への距離のCPU回帰テストと、この実GPUでの結果は整合するため、今回の中心位置の退行は修正できたと判断する。

画像だけから全粒子の3D距離を証明したわけではない。面ごとの文字の重なり、細い茎からはみ出す文字板、葉を横から見たときのほぼ線になる表示、三角形の境界を越えた文字板の角の隠れは残る。これらは文字板が一つの面に載る方式の既存の制限であり、面内の中心そのものが別の曲面へ沈む今回の問題とは区別する。

固定領域内の明るい画素数も記録した。遮蔽や向きで変化するため面被覆率そのものではないが、今回の三つの時刻で大きな欠落が起きていない補助指標になる。

| 素材 | 0秒 | 8秒 | 16秒 |
|---|---:|---:|---:|
| 木 | 45,599 | 45,008 | 45,233 |
| 花 | 22,900 | 22,353 | 22,102 |
| きのこ | 47,662 | 48,575 | 48,618 |

画面は`screens/`、各時点の時刻・設定・GPUエラーは`screens/results.json`、測定に使ったソースのSHA256と画素数は`verification-metadata.json`に保存した。

## 馬モデルでの一度の速度測定

別担当の8Bモデルの推論終了を確認してから開始した。TripoSRの馬GLB（64,254頂点）を画面から読み込み、4,096文字、面を歩く、形の揺らぎ1、流れ1、回転off。30フレームのウォームアップ後に240フレームのrAF間隔を採取した。

| 指標 | 実測 |
|---|---:|
| 中央値 | 16.70 ms |
| p95 | 16.70 ms |
| p99 | 16.80 ms |
| 最大 | 16.80 ms |
| 平均 | 16.66625 ms |
| JS / console / GPUエラー | 0 / 0 / 0 |

この約4秒の計測では60 Hz相当で表示できた。rAF間隔はフレームの提示間隔であり、GPU処理そのものの実行時間ではない。長時間の負荷試験、複数体、異なる画面密度・機種は測定していない。再試行による良い値の選別は行わず、測定は一度だけ。生の240間隔と設定は`performance/results.json`、その画面は`performance/horse-4096.png`。

## 再現
