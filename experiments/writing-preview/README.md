# 続けて書く — 独立入口

**Powered by Stability AI**

2026-09-30 / Apple M5 32GB / 既定画面と旧リポジトリは変更しない。

試遊: 開発サーバーの **http://127.0.0.1:4183/src/writing-preview/index.html** 。黒い画面と下部の入力欄だけを別入口に置いた。通常の `/` は従来どおり。生成には既存の説明API 4188・画像経由API 4187が必要。文字だけと明示属性の編集はAPIなしで動く。

## この試作で確かめること

形の生成を待ちながら文章を追加できるかを確かめる。モデルに新規作成・編集・維持の判断を委ねる実験は採用しない。送信前に次の操作を自分で選ぶ。

| 操作 | 文字の扱い | 形の扱い |
|---|---|---|
| 文章から形を作る | 受理直後に追加 | 日本語原文 → ローカル説明API → SDXL Turbo → U2NETP → TripoSR |
| 今の形を変える | 受理直後に追加 | `localAttributeEdit` が完全な属性命令と認めたものだけを適用。例: 四角く、ねじれた、3個 |
| 文字だけ加える | 受理直後に追加 | 変更しない。初期選択はこちら |

操作は送信時のIDに固定する。同じ原文を異なる操作で送っても混同せず、再試行中に選択を変えても元の操作を使う。原文は空白・改行・正規化前の文字列を履歴に残す。表面の字だけは共通 `LetterField` によりNFC書記素単位へ分かれ、空白は除かれる。色指定はその段落の字だけに適用する。色なしは共通描画の赤→白変化を用いる。

**履歴の「受理」は原文を受け取ったという意味で、立体の生成成功を意味しない。** 生成の状態・失敗・再試行は入力欄の下に別表示する。モデル失敗でも、原文と追加済みの字は消さない。

## 待機と取消

- 共有 `ContinuousInput` を使用し、解釈と生成を同時に1件だけ処理する。送信は待機8件まで受け付け、実行中は別枠。
- 後から届いた段落を先に解釈してから、生成済みメッシュを採用する。新対象の段落なら古い生成を捨て、属性命令なら新対象の完成時にその属性を適用する。文字だけの段落は生成対象を変えない。
- `current` はこれから表示する対象、`displayed` は実際に表示済みの対象として分ける。未知物体を描く内部の `sphere` 属性用フォールバックを、その物体の意味として保存しない。
- 「待機を取り消す」は現在表示済みの形を保ち、未完ジョブを無効化する。追加済みの文字も入力途中の欄も保つ。実行中のローカル推論そのものを中断する機能ではないため、その処理が終了するまで次の形処理は待つ。
- GLB読込には世代判定と `scene.invalidateLoads()` を併用する。取消後に遅れて読込が終わっても、旧形を再表示しない。Blob URLは読込の成否にかかわらず解放する。
- 再試行は原文の同じIDを使い、文字の追加を繰り返さない。生成の再試行は最新の同一対象の属性を使う。
- 生成失敗の後に別の入力も失敗した場合は、入力の再試行と「形の生成を再試行」を分けて出す。無効な属性命令の失敗で、先行する生成の再試行手段を失わない。

## 制限

- 1段落2000 Unicode code point、表面4096書記素（初期の `@` を含む）。超過時に切り詰めず、全文を入力欄へ残して拒否する。
- Enterで送信、Shift+Enterで改行。IME変換中と変換確定後80msは送らない。
- 原文・待機状態はページのメモリ内だけ。ファイルやlocalStorageへ自動保存しない。ページの再読込・終了で失われる。原文履歴から手動でコピーできる。
- 自由な文章から必ず意図した物体が得られるわけではない。属性変更も既定の数値へ置き換える限定された規則であり、任意の部分編集ではない。
- 画面は共通の三平面投影texture方式。文字の重なり・伸びの既存制限を持つ。独立した3D表面流体ではない。
- 取消後も原文履歴を残す。世代が変わった古い失敗の再試行は出さない。履歴は原文の保全用で、全生成物のバージョン一覧ではない。

## 検証

[mock-v3/results.json](mock-v3/results.json) の12群が通過。人工文章、既存人工じょうろGLB、HTTP mockのみで実モデルは呼んでいない。

1. 生成中の原文・色の即時追加、表示済み対象の保持、後追い属性の完成時適用。
2. 同一原文の別操作、再試行時に同じID・元の操作を使う。
3. 遅延生成中に新対象が来たとき、旧生成を採用しない。
4. 生成失敗から再試行しても文字は増えず、後の編集が反映される。
5. 否定や物体名を含む不完全な属性命令を拒否し、原文を保持。
6. IME変換と80ms保護、複数行の原文保持。
7. 2000/4096の境界で部分受理しない。
8. 待機8件超過で入力欄を保持、取消後も実際の未知物体のidentityを維持。
9. 説明中の取消は画像生成へ進めず、次の入力は動く。
10. GLB読込中の取消は旧形を表示せず、Blob URLを解放。
11. 壊れたGLBの失敗と再試行で2つのBlob URLを両方解放し、文字は一度だけ追加。
12. 生成503の後に無効な「大きく」の編集が失敗しても、形の生成だけを再試行できる。2原文は重複しない。

全ケースのJS例外・予期しないconsole error・GL error・外部リクエストは0。意図的に返した422/503のブラウザresource errorだけは期待したHTTPエラーとして結果に残した。初回 [mock-v1](mock-v1/results.json) はその2つをテスト側がJSエラーと同列に扱ったため7/9通過となった。UI挙動は通っていたが、初回記録を削除せず、新記録で区別を修正した。

型検査 `npx tsc --noEmit` 通過。共有ハーネスの変更はroot担当による、後方互換の `route(text,current,writing)` 第3引数追加、および生成失敗と入力失敗の再試行経路の分離。この入口専用のコードは [src/writing-preview](../../src/writing-preview/) に分離した。[mock-v2](mock-v2/results.json) の11群も保存し、生成失敗と入力失敗の競合を12番目として追加した。

v0.5ではこの入口も `npm run build` に含め、生成済みファイルからの[実操作9項目](../surface-05/RESULTS.md)も通過した。

再実行は未使用の出力名を指定する（既存出力を上書きしない）。

```sh
node experiments/writing-preview/mock-browser.mjs mock-repeat
node experiments/writing-preview/real-browser.mjs real-repeat
node experiments/writing-preview/real-browser.mjs fixture-repeat --fixture-replay
```

`real-repeat` は実際のローカルモデルを1回呼ぶため、他のGPU推論と同時に実行しない。`--fixture-replay` は既存花瓶の再生だけで、推論しない。

## 実モデル1回と保存処理の再生確認

[real-v1の評価](real-v1/ASSESSMENT.md)、[応答・待機中・完成時の状態](real-v1/results.json) を保存した。人工文「取っ手が二つ付いた丸い花瓶」は4.443秒で `a round vase with two handles` となり、21.007秒で画像経由の立体を得た。3原文・26字の即時追加と、後追いの「四角く」の反映は成立した。

ただし検証はfaviconの404で失敗し、Playwrightによる保存GLBも0 bytesだった。両方を実行成功と混ぜず残している。faviconを修正後、[fixture-replay-v1](fixture-replay-v1/results.json) で以前の人工花瓶GLBをAPI mockから返し、実際に消費するBlobからのコピーを確認した。390356 bytes、元ファイルのSHA256と一致、GL/JS/外部リクエスト0。これは**real-v1で生成されたモデルの再生ではなく、別の既存花瓶による保存経路の検証**である。モデルをもう一度呼んではいない。

採用範囲は、操作を明示すれば原文を失わず生成を待てる別入口。形の意味の精度、長文からの適切な対象選択、任意部分編集を解決したものではない。既定画面へ自動振り分け機能を戻す根拠にも使わない。
